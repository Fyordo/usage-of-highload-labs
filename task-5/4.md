Я указал enp0s3, т.к. он является моим основным сетевым адаптером на виртуальной машине.

Основные возможности разгрузки:
1. Контрольные суммы (Checksum Offloading):
   - RX Checksumming: Отключено. Прием пакета не включает автоматическое выполнение проверки контрольных сумм.
      
   - TX Checksumming: Включено через реализацию IP Generic

Контрольные суммы необходимы для проверки целостности передаваемых данных. Мой адаптер способен автоматически рассчитывать
контрольные суммы для большинства типов пакетов, кроме определенных случаев, которые жестко определены оборудованием.

2. Сборка-разборка пакетов (Scatter-Gather Support):
   Scatter-Gather: Включено
   TX Scatter-Gather: Включено
   TX Scatter-Gather-FragList: Отключено и зафиксировано

Эта функция помогает собирать фрагменты пакетов и отправлять их единым потоком, уменьшая нагрузку на процессор.

3. ТСР-сегментация (TCP Segmentation Offload):

   TCP Segmentation Offload: Включено
   TX TCP Segmentation: Включено
   TX TCP ECN Segmentation: Отключено и зафиксировано
   TX TCP MangleID Segmentation: Отключено
   TX TCP6 Segmentation: Отключено и зафиксировано

Устройство поддерживает ускоренную передачу больших объемов данных путем автоматической сегментации TCP-пакетов.
Тем не менее, IPv6 и ECN-сегментация невозможны из-за ограничений оборудования.

4. Общие сегменты (Generic Segmentation Offload):

   Generic Segmentation Offload: Включено
   Generic Receive Offload: Включено
   Large Receive Offload: Отключено и зафиксировано

Обработка общего сегмента ускоряет прием большого количества маленьких пакетов,
объединяя их в крупные блоки для дальнейшей обработки.

5. Возможности VLAN:

   VLAN Offloading: Включены Rx VLAN и Tx VLAN (on, фиксируется).
   Другие специализированные VLAN-функции (например, Ntuple filters) отключены и фиксируются.

Адаптер способен обрабатывать стандартные VLAN-метки при приеме и передаче пакетов.

6. Дополнительные возможности разгрузки:

   HighDMA, Loopback, Receive Hashing, HSR, TLS Hardware Offload, ESP-HW-Offload и многие другие функции отключения фиксированы или отключены по умолчанию.

Эти продвинутые функции разгрузки либо заблокированы в моей сетевой карте, либо отключены на уровне виртуальной машины.

**ИТОГО:**

Сетевой адаптер имеет хорошие базовые возможности разгрузки для повышения производительности сети,
такие как включенная обработка контрольных сумм, сборка-разборка пакетов и TCP-сегментация.
Однако некоторые высокоуровневые функции, такие как IPv6-контрольные суммы и большой объем приема,
отключены и не могут быть активированы.

### Описание его задачи

**TCP Segmentation Offload (TSO)** — это технология аппаратного ускорения,
которая переносит задачу сегментации TCP-пакетов с центрального процессора (ЦП) на сетевой адаптер (NIC).

Какую задачу решает TSO:
- **Сегментация TCP**: При отправке большого объема данных по сети, протокол TCP/IP разбивает эти данные на более мелкие фрагменты (сегменты),
размер которых не превышает максимальный размер сегмента (MSS). Этот процесс называется сегментацией.
- **Нагрузка на ЦП**: Традиционно сегментация выполняется программным обеспечением — сетевым стеком операционной системы — на центральном процессоре.
При высокой сетевой активности это может потреблять значительные ресурсы ЦП.
- **Разгрузка ЦП**: TSO позволяет сетевому стеку передавать сетевому адаптеру для отправки один очень большой пакет данных (например, размером до 64 КБ).
Сетевая карта, поддерживающая TSO, самостоятельно разбивает этот большой пакет на правильные TCP-сегменты, соответствующие MSS, и добавляет к каждому сегменту необходимые заголовки TCP/IP, прежде чем отправить их в сеть.

Главная цель TSO — снизить нагрузку на центральный процессор при интенсивном исходящем трафике, тем самым высвобождая ресурсы ЦП для других задач.
Эта функция особенно важна для высокоскоростных сетей.
